## 功能一：用户注册与登录系统

### 实现思路
- 用已安装的 **next-auth v4** + **Credentials Provider** 做邮箱密码登录。
- Prisma `User` 模型增加 `passwordHash`、`role`（user/admin）字段；密码用 `bcryptjs` 哈希。
- 新增 `/register`、`/login` 页面；`/api/auth/[...nextauth]/route.ts` 配置 Provider。

- 主页 header 右上角显示登录状态/用户名/登出按钮。
- 首次注册或通过脚本创建一个 `role=admin` 的超级管理员用于功能二。

### 数据模型变更（prisma/schema.prisma）

## 功能二：后端统计能力与管理员后台

### 实现思路
- 新增三张表记录使用数据：
  - `UsageEvent`：用户行为埋点（登录、上传PDF、发起分析、发起对话、划词翻译等）。
  - `ChatLog`：每条 agent 回答的完整记录（用户id、问题、回答、paperId、时间戳）。
  - `Feedback`：用户对 agent 回答的点赞/点踩（关联 ChatLog，含可选原因文本）。
- 在业务 API（analyze/chat/translate）中异步写入埋点（需登录态，从 session 取 userId）。
- 新增 `/admin` 路由（仅 role=admin 可访问，middleware 校验），用 **recharts** 展示：
  - 活跃用户数趋势、每日上传/对话/翻译次数。
  - 最近用户列表、最近对话。
  - **点踩回答清单**：列出所有 feedback.type=down 的记录，含原问题、原回答、点踩原因、用户、时间，支持按时间/用户筛选。
- 管理员后台也用 shadcn/ui + recharts，保持高级感配色。

### 数据模型
```prisma
model ChatLog {
  id        String   @id @default(cuid())
  userId    String
  user      User     @relation(fields:[userId], references:[id])
  question  String
  answer    String
  paperTitle String?
  createdAt DateTime @default(now())
  feedbacks Feedback[]
}

model Feedback {
  id        String   @id @default(cuid())
  chatLogId String
  chatLog   ChatLog  @relation(fields:[chatLogId], references:[id], onDelete: Cascade)
  userId    String
  user      User     @relation(fields:[userId], references:[id])
  type      String   // "up" | "down"
  reason    String?  // 点踩时可选的改进建议
  createdAt DateTime @default(now())
  @@unique([chatLogId, userId])  // 每个用户对每条回答只能反馈一次
}

model UsageEvent {
  id        String   @id @default(cuid())
  userId    String?
  user      User?    @relation(fields:[userId], references:[id])
  action    String   // "login"|"upload_pdf"|"analyze"|"chat"|"translate"|"vision"
  meta      String?  // JSON 字符串，存额外信息如 paperTitle
  createdAt DateTime @default(now())
}
```

## 功能三：PDF 解析算法升级

### 实现思路
当前用 `pdfjs.getTextContent().items.map(it=>it.str).join(" ")`，丢失了段落、表格、公式、双栏版面，导致大纲分析质量受限。升级方案（按投入由低到高，推荐方案B）：

- **方案A（轻量改进，纯前端）**：利用 pdfjs 的 `item.transform`（位置矩阵）和 `item.hasEOL` 重建段落与阅读顺序：按 Y 坐标分块成行，行间距超阈值断段；识别双栏（X 坐标聚类）先左栏后右栏拼接。表格用 `getOperatorList` 或 text 的 X 对齐启发式粗识别。零成本、无需后端，但表格/公式仍弱。
- **方案B（推荐，服务端结构化解析）**：上传 PDF 到服务端，用 **MinerU** / **Marker** / **GROBID** 之一做版面+表格+公式解析，输出 Markdown/JSON。MinerU 对学术 PDF（含公式表格双栏）效果最好，可本地部署或调 API。解析后把结构化文本用于 analyze，原文 PDF 仍用 pdfjs 渲染。
- **方案C（云端 API）**：接 Mathpix / Adobe PDF Services API，付费但最省事。

建议组合：**服务端 MinerU 解析产出 Markdown 喂给 analyze；前端 pdfjs 仅做渲染与划词**。上传改为先传服务端 `/api/upload` 持久化 + 触发解析任务，前端轮询或 SSE 获取解析结果。

### 【提示词】
```

目标方案（服务端结构化解析）：
1. 新建 src/app/api/upload/route.ts：接收 multipart PDF 上传，保存到 uploads/ 目录（用 cuid 命名），创建一条 Paper 记录（Prisma：Paper 模型含 id/userId/title/parseStatus[pending|done|error]/parsedText/createdAt）。异步触发解析。
2. 新建 src/lib/pdf-parse.ts，封装解析逻辑，优先级如下（按可用性自动降级）：
   a) 调用本地 MinerU 服务（环境变量 MINERU_API_URL），POST PDF，轮询拿回 Markdown 结果。
   b) 若 MinerU 不可用，回退到 Python 子进程调用 marker（marker_single 命令）。
   c) 再回退：用 pdfjs（服务端 @affinidi/tck-pdfjs-dist 或 node 端 pdfjs）+ 位置重建：按 item.transform[5](Y) 与 hasEOL 重排行，行间距>阈值断段，X 坐标聚类识别双栏先左后右。
   解析结果为 Markdown 字符串，存入 Paper.parsedText，parseStatus 置 done。
3. 修改 src/app/api/analyze/route.ts：改为接收 { paperId } 或仍兼容 { text }；优先从 Paper.parsedText 取结构化文本，截断长度提升到 30000 字符（结构化文本信息密度更高）。
4. 修改 src/app/page.tsx 的 onFile：上传走 /api/upload，拿到 paperId 后轮询 /api/paper/[id] 获取 parseStatus；done 后再调用 analyze。上传中显示进度（"上传中→解析中→分析中"三态）。解析期间 PDF 仍可立即用 pdfjs 预览。

如果部署环境无法跑 MinerU/marker，请确保降级路径 c) 至少实现"按 Y 坐标分行 + 行间距断段 + 双栏识别"，并保留注释说明如何切换到 MinerU。解析后的文本要保留 [Page N] 页码标记，供大纲 quote 跳转定位使用。
```

## 功能五：手动调节界面比例（上下拖拽翻译框 / agent 框）

### 实现思路
项目已安装 `react-resizable-panels` 但未启用。当前右侧翻译/对话用固定 `h-[42%]`/`flex-1`。改为：
- 右侧 aside 用 `<PanelGroup direction="vertical">` 包两个 `<Panel>`（翻译 / 对话），中间 `<PanelResizeHandle>` 可上下拖拽。
- 顺带把左侧大纲 / 中间 PDF / 右侧的整体三栏也改成 `<PanelGroup direction="horizontal">`，让左右宽度也可调，更灵活。
- Handle 要有明显视觉反馈（hover 高亮、拖拽光标），但不破坏高级感。

```
不要改变各子组件（PdfViewer/OutlinePanel/TranslationPanel/ChatPanel）的 props 接口，只改 page.tsx 的布局外壳。确保拖拽时 PDF 渲染不抖动（pdf-viewer 容器用 ResizeObserver 自适应即可，一般无需改）。
```

## 功能六：Agent 回答点赞点踩 + 延伸问题引导

### 实现思路
- 在 `ChatPanel` 的每条 assistant 消息下方加 👍 / 👎 两个按钮；点击调用 `/api/feedback`（功能二已建）。
- 点踩时弹一个可选的"改进建议"输入框（Popover 或内联 Textarea），提交后写入 Feedback.reason。
- agent 回答完成后，**额外发起一次 LLM 调用**生成 3 个相关延伸问题，以可点击的卡片形式显示在回答下方；用户点击某个延伸问题即自动填入输入框并发送。
- 延伸问题生成提示词：基于当前问答上下文 + 论文内容，生成 3 个由浅入深的追问。

### 【提示词】
```

一、点赞点踩：
1. ChatMessage 类型增加 chatLogId?(string)、feedback?: "up"|"down"|null、followUps?: string[] 字段。

风格：按钮和卡片用 shadcn Button variant=ghost size=sm，配色遵循功能八，不要花哨。延伸问题卡片要有"可点击追问"的视觉暗示（如右侧 ChevronRight）。
```

## 功能七：导入文章生成思维导图（可与原文 PDF 切换）

### 实现思路
- 导入 PDF 并完成 analyze 后，**额外**生成一份思维导图数据（可直接复用 analyze 的 6 维度 JSON，或单独调用一次 LLM 生成更精简的树形结构）。
- 在中间 PDF 展示区顶部加一个 **"原文 / 思维导图"切换 Tab**：
  - 原文模式：现有 PdfViewer。
  - 思维导图模式：用 **reactflow**（或 markmap-lib + markmap-view）渲染树形思维导图；节点可点击跳转到对应原文位置（复用 quote 跳转逻辑）。
- 思维导图节点配色按 6 维度分区上色（呼应功能八）。
- 推荐用 reactflow，可控性强、易做交互；markmap 更省事但定制弱。

### 【提示词】
```
在中间 PDF 展示区实现"原文 PDF / 思维导图"双视图切换。补装 reactflow（@xyflow/react）。

一、数据：复用 /api/analyze 返回的 6 维度 outline JSON，转换成 reactflow 的树形节点。新建 src/lib/outline-to-flow.ts：把 sections→children 递归转为 {id,type:'input|default|output',data:{label},position,parent,style} 节点与 edges。根节点为论文标题，第二层为 6 个维度，第三层为各 children。6 个维度节点按功能八的分区色板上色（如科学问题=主蓝、论证思路=青、实验方法与结果=紫、论证逻辑解析=橙、创新性=绿、局限性=红/粉）。

二、UI：在 src/app/page.tsx 的中间 main 区域顶部加一个 shadcn Tabs：Tab1="原文 PDF"（渲染现有 PdfViewer），Tab2="思维导图"（渲染新组件 MindmapView）。
- 切换 Tab 时 PDF 不卸载（用 hidden 隐藏而非条件渲染），避免重新加载。
- MindmapView 用 reactflow 的 ReactFlow + Background + Controls + MiniMap，布局用 dagre（@dagrejs/dagre）自动排版成横向树。节点自定义：维度节点显示维度名+summary，children 节点显示标题。

三、思维导图生成时机：analyze 返回后即有数据，无需额外 API。若想要更精简的导图，可在 analyze 完成后异步调一次 /api/mindmap 生成精简树（可选，非必须）。

四、MiniMap 与 Controls 用浅色主题匹配整体配色。导图区域背景用极浅灰，节点圆角 8px，边用平滑 bezier。整体高级感，不要默认的 reactflow 蓝紫配色。

注意：pdf-viewer.tsx 的 props 不变；page.tsx 用 useState activeView('pdf'|'mindmap') 控制 Tab。Tab 切换时若尚未上传 PDF，思维导图 Tab 显示空态提示"导入 PDF 后自动生成"。
```

## 功能八：分区配色与高级感视觉升级

### 实现思路
当前整体是 shadcn 默认中性灰 + primary 蓝，缺乏分区识别度与高级感。目标：
1. 定义一套**高级感色板**：低饱和、冷暖协调，6 个维度各有标识色，整体深浅有层次。
2. 用 Tailwind v4 的 CSS 变量（`globals.css` 里 `:root` / `.dark`）统一管理；shadcn 的 `--primary`、`--accent` 等仍可用，但新增 `--dim-1`…`--dim-6` 维度色变量。
3. 各面板（大纲/翻译/对话/PDF）用微差的背景色 + 细边框区分，而非全部纯白；header 用深色玻璃质感。
4. 字体层级、间距、圆角、阴影统一规范。

### 推荐配色（低饱和高级感，浅色主题）
```
背景层级：
  --background: #FAFBFC      （极浅冷灰）
  --card:      #FFFFFF
  --muted:     #F1F3F5
  --border:    #E5E9EE
  --foreground:#1A2230        （深蓝灰，比纯黑柔和）

主品牌：
  --primary:   #2C5F8D       （沉稳学术蓝，比默认亮蓝高级）
  --primary-foreground: #FFFFFF

6 维度标识色（低饱和，用于大纲/思维导图/延伸卡片）：
  --dim-1 科学问题:        #2C5F8D  (深蓝)
  --dim-2 论证思路:        #3F8E83  (青绿)
  --dim-3 实验方法与结果:  #6B5B95  (雾紫)
  --dim-4 论证逻辑解析:    #C08552  (赭橙)
  --dim-5 创新性:          #5B8C5A  (橄榄绿)
  --dim-6 局限性:          #B0546E  (玫红)

强调/状态：
  --accent:    #E8EEF4
  --success:   #5B8C5A
  --warning:   #C08552
  --destructive:#B0546E
```
深色主题对应降低明度、提高饱和度的版本。

### 【提示词】
```
对整个应用做视觉升级，建立高级感分区配色体系。

一、在 src/app/globals.css 的 :root 与 .dark 中定义上述 CSS 变量（--background/--card/--muted/--border/--foreground/--primary/--primary-foreground/--dim-1..--dim-6/--accent/--success/--warning/--destructive）。Tailwind v4 用 @theme inline 把这些变量映射为 tailwind 颜色 token（如 --color-dim-1: var(--dim-1)），使 className="text-dim-1"/"bg-dim-1" 可用。

二、各面板分区用微差背景区分：
  - 左侧大纲 aside：bg-card，维度标题左侧加 4px 宽的对应 dim 色竖条。
  - 中间 PDF 区：bg-muted/40，顶部 Tab 栏 bg-background/80 backdrop-blur 玻璃质感。
  - 翻译面板：bg-card，顶栏用 dim-2 色淡背景条。
  - 对话面板：bg-card，assistant 气泡用 accent 色，user 气泡用 primary 色。
  - header：bg-foreground 文字用 background 色（深色顶栏），logo 用 primary。
三、统一规范：圆角 rounded-lg(8px)、卡片阴影 shadow-sm、边框 border-border、间距用 4/8/12/16 倍数。正文字号 14px、标题 13px semibold、辅助 11px muted-foreground。
四、6 维度色应用：大纲每个 section 标题前的图标圆点用对应 dim 色；思维导图节点用 dim 色；延伸问题卡片左边框用 dim 色；点赞点踩按钮 active 态用 success/destructive。
五、整体去掉默认 shadcn 的亮蓝（#18181b 体系）与过于扁平的感觉，增加 1px 边框 + 极轻阴影的层次。深色主题同步实现。

不要引入新依赖。只改 globals.css 与各组件的 className。确保 light/dark 都有。修改后逐一检查大纲/翻译/对话/PDF/思维导图/管理员后台六个区域视觉一致。
```

## 附：实施顺序建议

按依赖关系与风险排序，建议分 4 个批次提交给编码 AI：

1. **批次A（基础设施）**：功能八配色 → 功能五可调布局。先定视觉地基再填功能，避免返工。
2. **批次B（内容核心）**：功能四结构化提示词 → 功能三PDF解析升级。这俩是内容质量根基。
3. **批次C（交互增强）**：功能七思维导图 → 功能六点赞点踩+延伸问题。
4. **批次D（用户系统）**：功能一注册登录 → 功能二管理员后台。最后做，因为需要真实用户数据才体现统计价值。

每批次完成后 `bun run build` 验证编译，`prisma db push` 同步表结构，本地 `bun run dev` 跑通再进下一批。

## 附：可选的 Prisma 完整 schema 参考

把功能一、二、三的数据模型合并后的最终 schema 骨架：

```prisma
generator client { provider = "prisma-client-js" }
datasource db { provider = "sqlite"; url = env("DATABASE_URL") }

model User {
  id           String       @id @default(cuid())
  email        String       @unique
  name         String?
  passwordHash String
  role         String       @default("user")
  createdAt    DateTime     @default(now())
  updatedAt    DateTime     @updatedAt
  chatLogs     ChatLog[]
  feedbacks    Feedback[]
  events       UsageEvent[]
  papers       Paper[]
}

model Paper {
  id          String   @id @default(cuid())
  userId      String
  user        User     @relation(fields:[userId], references:[id])
  title       String
  filePath    String
  parseStatus String   @default("pending")  // pending|done|error
  parsedText  String?
  createdAt   DateTime @default(now())
}

model ChatLog {
  id         String     @id @default(cuid())
  userId     String
  user       User       @relation(fields:[userId], references:[id])
  paperId    String?
  question   String
  answer     String
  paperTitle String?
  createdAt  DateTime   @default(now())
  feedbacks  Feedback[]
}

model Feedback {
  id        String   @id @default(cuid())
  chatLogId String
  chatLog   ChatLog  @relation(fields:[chatLogId], references:[id], onDelete: Cascade)
  userId    String
  user      User     @relation(fields:[userId], references:[id])
  type      String   // up | down
  reason    String?
  createdAt DateTime @default(now())
  @@unique([chatLogId, userId])
}

model UsageEvent {
  id        String   @id @default(cuid())
  userId    String?
  user      User?    @relation(fields:[userId], references:[id])
  action    String
  meta      String?
  createdAt DateTime @default(now())
}
```
